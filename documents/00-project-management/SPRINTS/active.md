# Active Sprint

No sprint is currently active on `dev`. The most recently closed sprint is **Sprint R09d — Room-scoped previous playback command** (closed 2026-07-01, accepted by the Product Owner 2026-07-01). R09d adds one lease-holder-only HTTP slice (`POST /api/rooms/{slug}/playback/prev`, behind `roomAuth`, empty body), one additive per-room WebSocket event (`room_playback_song_previous`), and a minimal frontend Prev control surface in RoomView (gated on the existing lease-holder UI affordance AND on `current_index > 0`). The command requires a valid current song and `CurrentIndex > 0`; on success it decrements `CurrentIndex`, sets `Elapsed = 0`, sets `Status = playing`, and persists the room queue. On no-current-song or already-first-song the command returns `400` with no mutation, no save, and no broadcast. A new `entity.Queue.PrevToPrevious` helper mirrors `AdvanceToNext`'s no-partial-mutation invariant, and a local `roomqueue.ErrNoPreviousSong` sentinel is added so the handler maps cleanly to 400 without string-matching the legacy `Queue.Prev()` error. Auto-queue is NOT triggered. The global `/api/queue/prev` contract, the global `/ws` 16-event inventory, voting, priority balances, Docker, CORS, and auth/session design remain untouched. See the *Implementation summary (R09d)* section in [014-player-control-semantics.md](./014-player-control-semantics.md).

Sprint 016 / R09c — Room-scoped volume command is closed (2026-06-30, accepted by the Product Owner 2026-07-01). R09c adds one backend-only HTTP slice (`POST /api/rooms/{slug}/playback/volume`, behind `roomAuth`), one additive per-room WebSocket event (`room_playback_volume_changed`), and a narrow frontend wiring (one API method + one listener + a small Vol± control surface in RoomView, gated by the same lease-holder UI affordance as the R09a playback panel). Volume is intentionally NOT persisted: there is no `entity.Queue.Volume` field, no `room_queue_state` schema change, and the command does not call `queueRepo.Save`. The global `/api/queue/volume` contract, the global `/ws` 16-event inventory, voting, priority balances, auto-queue, Docker, CORS, auth/session design remain untouched. The closure pass tightened two narrow UX details on `dev`: the frontend toast on `room_playback_volume_changed` now uses an explicit up/down branch (a non-up/down payload reads as a neutral "Volume changed." rather than silently defaulting to "decreased"); and the WS hub test file ends with a trailing newline matching the rest of the suite. See the *Implementation summary (R09c)* section in [014-player-control-semantics.md](./014-player-control-semantics.md).

Sprint 015 / R09b — Room vote-to-skip backend contract is closed (2026-06-30, accepted by the Product Owner). R09b adds one backend-only HTTP slice (`POST /api/rooms/{slug}/vote/skip`, behind `roomAuth`), two additive per-room WebSocket events (`room_vote_updated`, `room_vote_resolved`), and an additive reuse of the existing `room_playback_song_advanced` event (with `reason: "skip"`) when the vote passes. Vote sessions live in a new `internal/usecase/roomvote` package: in-memory, room-scoped, current-song-scoped, 30-second expiry, single-instance only, never persisted. Threshold is captured at session creation via a new `(*RoomWSHub).UniqueConnectedUserIDs(slug) int` (de-duplicates by `userID`) using strict-majority `max(2, n/2 + 1)` with a 2-voter minimum. The global `/api/vote/skip`/`/api/vote/prioritize`, global `/api/queue/...`, global `/ws` 16-event inventory, vote thresholds, priority balances, auto-queue, Docker, CORS, auth/session design, and frontend UI remain untouched. See the *Implementation summary (R09b)* section in [014-player-control-semantics.md](./014-player-control-semantics.md).
