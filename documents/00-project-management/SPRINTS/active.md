# Active Sprint

Sprint 015 / R09b — Room vote-to-skip backend contract is the currently active sprint on `dev` (not yet accepted by the Product Owner). R09b adds one backend-only HTTP slice (`POST /api/rooms/{slug}/vote/skip`, behind `roomAuth`), two additive per-room WebSocket events (`room_vote_updated`, `room_vote_resolved`), and an additive reuse of the existing `room_playback_song_advanced` event (with `reason: "skip"`) when the vote passes. Vote sessions live in a new `internal/usecase/roomvote` package: in-memory, room-scoped, current-song-scoped, 30-second expiry, single-instance only, never persisted. Threshold is captured at session creation via a new `(*RoomWSHub).UniqueConnectedUserIDs(slug) int` (de-duplicates by `userID`) using strict-majority `max(2, n/2 + 1)` with a 2-voter minimum. The global `/api/vote/skip`/`/api/vote/prioritize`, global `/api/queue/...`, global `/ws` 16-event inventory, vote thresholds, priority balances, auto-queue, Docker, CORS, auth/session design, and frontend UI remain untouched. See the *Implementation summary (R09b)* section in [014-player-control-semantics.md](./014-player-control-semantics.md).
